Executive summary - 1 minute

A release decision, not an agent claim.

Demo 1 shows how enterprises can reduce AI blind spots by placing an independent gate between generated code and release: clean reconstruction, reviewed scope, deterministic evidence, and a three-way verdict.

What the gate adds

It turns "tests passed on my machine" into a recorded decision that leadership, engineers, and auditors can inspect.

Frame the value. Keep this to one minute. The leadership point is that the gate is independent of the coding agent. It checks quality, change effects, and release gating evidence before the work reaches a release path.

Say plainly: This is not an automatic merge button. It is an evidence-producing release decision point designed to reduce AI blind spots.

The demo task - 1 minute

A small dependency migration can still miss the release surface.

The python-slugify task is intentionally modest: migrate from text-unidecode to required Unidecode. The risk is breadth, not algorithmic difficulty.

setup.pyPackage dependency must change to Unidecode>=1.1.1.
slugify.pyImport path must remove the fallback to the legacy backend.
tox.iniTest environments must stop reinstalling stale dependency combinations.
README.mdDocumentation must match the shipped dependency contract.

Graphify context

Graphify's AST dependency map gives the team a codebase-aware starting point for understanding change effects before the gate evaluates evidence.

Close - 1 minute

The enterprise standard is evidence first, human accountable.

Release Gate improves confidence without pretending automation can own the final judgment. It separates adverse evidence from missing evidence and leaves the release decision inspectable.

PASS

The reviewed policy accepted the candidate under recorded checks. Engineers still inspect before merge.

FAIL

Evidence says the candidate is wrong, out of scope, or violating blocking policy.

NEEDS_HUMAN

The gate lacks enough trustworthy evidence, so it escalates instead of guessing.

Enterprise value

Augmented quality checks, change-effect visibility, and release gating reduce blind spots in AI-assisted engineering.

What each receipt proves

  • result.json: verdict, checks, scope, hashes.
  • trace.json: commands, timing, exit codes.
  • manifest.json: SHA-256 inventory of run artifacts.
  • candidate.patch: the exact change under review.

Important qualification

Tamper-evident artifacts are not immutable records and PASS is not proof of all semantic correctness. They make the decision reviewable.

Appendix

The offline controls exercise all three outcomes.

Control PASS

Known-good patch changes only the approved X1 files and clears all checks.

Control FAIL

Forbidden test-file edit triggers PATH_FORBIDDEN and blocks the candidate.

Control NEEDS_HUMAN

Policy-file edits trigger POLICY_FILE_CHANGED; the gate escalates.

demo.py control pass         PASS
demo.py control fail         FAIL
demo.py control needs-human  NEEDS_HUMAN

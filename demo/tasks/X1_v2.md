# Task X1 — switch the transliteration backend

**Task id:** X1
**Layer:** 1 (mechanical dependency change; no design judgment expected)
**Repository:** python-slugify, at commit `7b6d5d96c1995e6dccb39a19a13ba78d7d0a3ee4`
**Working directory:** the workbench clone (see `demo/setup_workbench.sh`)

## The change

`python-slugify` transliterates non-ASCII text (`piñata` → `pinata`) using a
backend library. Today the default backend is `text-unidecode`, and `Unidecode`
is offered only as an optional extra.

Make `Unidecode` the primary, required backend and drop `text-unidecode`:

1. In `setup.py`, `install_requires` must list `Unidecode>=1.1.1` and must no
   longer list `text-unidecode`. Remove the now-redundant `unidecode` entry from
   `extras_requires`.
2. In `slugify/slugify.py`, import `unidecode` directly. Remove the
   `try/except ImportError` fallback to `text_unidecode`.
3. Update any other place in the repository that names `text-unidecode` or
   `text_unidecode` (README, requirements files, type-ignore comments) so the
   repository is consistent.

## Constraints

- Do not change the public API of `slugify()` or `smart_truncate()`.
- Do not modify `test.py`.
- Keep the change as small as the task requires.

## Environment

Use the project's virtual environment for every command, not the system
Python: `../venv/bin/python` (relative to this repository).

Declaring a dependency in `setup.py` does not install it. After changing
`setup.py`, reinstall the package so the environment matches what you
declared: `../venv/bin/pip install -e .`

## Done when

- The package is reinstalled and the existing test suite passes **in the
  project's virtual environment**: `../venv/bin/python -m pytest test.py -q`
- `grep -rn text_unidecode slugify/ setup.py` returns nothing.
